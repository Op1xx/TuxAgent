# Инструменты и политика безопасности (этап 3)

Документ фиксирует, как TuxAgent проверяет действия перед выполнением. Агентный
цикл подключён на этапе 4 и вызывает инструменты только через `ToolRegistry`;
устройство цикла описано в `docs/agent-loop.md`.

## Поток выполнения

```text
tool call
  → Tool.plan(arguments)         # валидация JSON-схемы + классификация риска
  → risk = safe / confirm / deny
  → confirm_dialog (только для confirm)
  → Tool.execute(plan, confirmed)
  → повторная проверка пути
  → действие без shell
  → проверка фактического результата
  → audit JSONL
```

`ToolPlan` содержит имя инструмента, проверенные аргументы, `RiskDecision`,
описание того, что будет затронуто, признак обратимости, предпросмотр и argv для
пакетных операций. `Tool.execute()` не выполняет план с уровнем `deny`, а план с
уровнем `confirm` требует `confirmed=True`.

## PathPolicy

`src/safety.py` приводит путь к `realpath` (`Path.resolve(strict=False)`), поэтому
`..` и симлинки не обходят проверку. Разрешённые корни по умолчанию — домашний
каталог и `/tmp`.

| Операция | Внутри `~` и `/tmp` | Вне `~` и `/tmp` | Защищённый путь |
|---|---|---|---|
| чтение / листинг без рекурсии | `safe` | `safe` | `safe` |
| рекурсивное чтение / поиск | `safe` | `confirm` | `deny` |
| `mkdir` / запись | `safe` | `confirm` | `deny` |
| перемещение / удаление | `confirm` | `deny` | `deny` |
| удаление корня `~` или `/tmp` | `deny` | — | — |

Защищённые пути: `/`, `/etc`, `/usr`, `/boot`, `/dev`, `/proc`, `/sys`, `/var/lib`.
Корень `/` защищён только сам по себе; иначе любой абсолютный путь считался бы
вложенным в защищённый каталог. Рекурсивные операции по защищённым путям
запрещены.

Для удаления и перемещения политика проверяет конечный симлинк. Если ссылка
ведёт за пределы разрешённой области, операция запрещается. При разрешённой
ссылке удаляется сама ссылка, а не её цель.

## Инструменты

| Инструмент | Риск | Что делает |
|---|---|---|
| `find_files` | `safe` / `confirm` / `deny` | поиск по glob-шаблону; шаблон — имя, не путь |
| `list_dir` | `safe` | содержимое каталога, скрытые файлы по флагу |
| `read_info` | `safe` | метаданные (`lstat`), без вывода содержимого файла |
| `mkdir` | `safe` / `confirm` / `deny` | создание каталога |
| `move_to_trash` | `confirm` | обратимое перемещение в XDG-корзину |
| `delete` | `confirm` / `deny` | безвозвратное удаление; каталог только с `recursive=true` |
| `package_search` | `safe` | поиск через `PackageManager` |
| `package_is_installed` | `safe` | проверка установки |
| `package_install` | `safe` | установка; после команды проверяется `is_installed` |
| `package_remove` | `confirm` | удаление пакетов; после команды проверяется `is_installed` |
| `package_update_index` | `safe` | обновление индекса |
| `package_clean_cache` | `safe` | очистка кэша |

Инструменты не принимают shell-команды. Файловые операции используют
`pathlib`/`shutil`, пакетные — только методы `PackageManager`, где argv собирается
из проверенных имён пакетов. `find_files` не следует по симлинкам и не показывает
ссылки, ведущие за пределы разрешённой области.

`move_to_trash` не требует внешней зависимости: файл переносится в
`~/.local/share/Trash/files`, рядом пишется `.trashinfo` с исходным путём и датой.
Каталог корзины можно подменить в тестах.

## Подтверждение

`ui/confirm_dialog.ui` + `src/confirm_dialog.py` показывают:

- что будет затронуто (`ToolPlan.summary`);
- обратимо ли действие;
- причину риска;
- предпросмотр argv, если он есть.

Кнопки — «Выполнить» и «Отмена». Для `safe` диалог не показывается, для `deny`
действие не выполняется. `ConfirmDialog.ask(plan)` возвращает `False` для `deny`,
`True` для `safe` и результат диалога для `confirm`.

## Audit

`AuditLogger` пишет JSONL в `<data_dir>/audit/audit.jsonl`. Поля записи:

- `timestamp` — UTC, ISO 8601;
- `tool` — имя инструмента;
- `argv` — фактический argv (для файловых инструментов пустой);
- `result` — сообщение об успехе или ошибке;
- `returncode` — код возврата, если он есть;
- `confirmed` — было ли подтверждение пользователя;
- `risk` — `safe` / `confirm` / `deny`;
- `details` — аргументы, путь и признак успеха.

Запись делается после выполнения или после ошибки выполнения. Отклонённые
политикой вызовы не выполняются и в журнал действий не попадают.

## Тесты

- `tests/test_safety.py` — разрешённые корни, защищённые пути, `..`, симлинки,
  unicode/пробелы/`--`, wildcard, рекурсивные запреты.
- `tests/test_tools.py` — схемы, файловые инструменты, корзина, guarded delete,
  audit, пакетные инструменты на фейковом менеджере, попытка инъекции.
- `tests/test_gui.py` — offscreen-проверка диалога подтверждения.

Реальные `apt`/`dnf`/`pacman`/`zypper` в тестах не запускаются.

## Ограничения

- При несовпадении ручного профиля дистрибутива с системой агент блокирует
  изменяющие пакетные операции до вызова `PackageManager`; такие отказы не
  попадают в audit, потому что действие не выполнялось.
- Проверка пути и само действие разделены, поэтому остаётся узкое TOCTOU-окно,
  если другой процесс подменит путь между ними. Для этапа 3 это осознанно:
  путь перепроверяется непосредственно перед действием.
- Для `package_update_index` и `package_clean_cache` подтверждение успеха — код
  возврата; для install/remove дополнительно проверяется фактическое состояние
  пакета.
- `/tmp` разрешён как рабочий корень, поэтому удаление там требует
  подтверждения, но не запрещено.
