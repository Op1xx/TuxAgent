# Агентный цикл (этап 4)

Документ описывает, как запрос проходит от поля ввода до отчёта. Реальная
модель пока не подключена: работает `MockBackend`, который отвечает по
сценариям из `resources/mock_scenarios.json`.

## Схема

```text
запрос
  → Agent.start()                       # сообщение пользователя + схемы инструментов
  → LLMBackend.complete()               # ответ: текст или tool calls
  → ToolRegistry.plan(name, args)       # схема, realpath, классификация риска
  → safe:      ToolRegistry.execute()   # выполнение без подтверждения
  → confirm:   AgentTurn(pending=plan)  # пауза, диалог спрашивает пользователя
  → deny:      результат «запрещено» возвращается модели
  → результат шага уходит обратно в модель
  → ... (не больше max_steps)
  → текст ответа + отчёт AgentReport
```

Модель не получает shell и не выполняет действия сама: она только предлагает
`ToolCall`, а превращает его в действие код приложения.

## Компоненты

| Модуль | Роль |
|---|---|
| `src/llm.py` | `Message`, `ToolCall`, `LLMResponse`, протокол `LLMBackend`, `MockBackend` |
| `src/agent.py` | цикл, лимиты, подтверждение, повторы, отчёт |
| `src/agent_worker.py` | `AgentTask(QThread)` — одна фаза цикла в фоне |
| `src/tools.py` | типизированные инструменты и `ToolRegistry` |
| `src/confirm_dialog.py` | диалог подтверждения для `confirm`-планов |

## Двухфазное подтверждение

`Agent.start()` выполняется в фоновом потоке и возвращает `AgentTurn`:

- `pending` заполнен — цикл остановился на плане, которому нужно подтверждение;
- `report` заполнен — цикл завершён.

Главный поток показывает `ConfirmDialog` и запускает `Agent.resume(allowed)`
новой фазой. Ответ «Отмена» прекращает весь запрос, а не только шаг: в отчёте
появляется `cancelled`, статус — «Отменено».

## Ограничения цикла

| Что | Значение | Поведение при превышении |
|---|---|---|
| шаги | `max_steps=8` | отчёт с причиной «Достигнут лимит шагов» |
| исправления tool call | `max_repairs=2` | отчёт с причиной «Не удалось исправить tool call» |
| таймаут инструмента | `tool_timeout=60` с | шаг помечается ошибкой, цикл продолжается |
| повтор | только `safe` и только исключения | одна повторная попытка |

Повтор не делается для `confirm`-планов и не повторяется при `ToolResult(ok=False)`:
детерминированная ошибка (например, «файл не найден») не станет успешнее от
второго запуска.

## Отчёт

`AgentReport` собирает фактически выполненные шаги (`AgentStepRecord`) и
проблемы. В чат он выводится отдельным сообщением:

```text
Выполнено:
• package_install — Установлено: firefox
Не выполнено:
• delete — Путь защищён политикой
Причина остановки:
• Достигнут лимит шагов (8)
```

Успех шага определяется `ToolResult.ok`, а он у пакетных и файловых
инструментов выставляется после фактической проверки состояния системы.

## MockBackend и сценарии

Файл `resources/mock_scenarios.json`:

```json
{
  "scenarios": [
    {
      "name": "install-package",
      "match": "(?:установи|поставь) (?:пакет )?(?P<package>[\\w.+-]+)",
      "steps": [
        {"tool": "package_is_installed", "arguments": {"package": "{package}"}},
        {"tool": "package_install", "arguments": {"packages": ["{package}"]}},
        {"reply": "Пакет {package} установлен."}
      ]
    }
  ],
  "fallback": {"reply": "Сценарий не найден."}
}
```

- `match` — регулярное выражение или список выражений (регистр не важен);
- группы подставляются в аргументы и ответы как `{name}` или `{1}`;
- сценарий выбирается по первому сообщению пользователя, шаги выдаются по
  порядку, после последнего шага возвращается «Готово.»;
- если ничего не совпало, возвращается `fallback.reply`.

`MockBackend` не проверяет существование инструмента и не знает о результате
его выполнения: это делает `Agent`, поэтому сценарии можно использовать для
проверки исправления tool calls и отчётов.

## Профиль дистрибутива

`build_agent()` в `src/main_window.py` собирает агента под настройки. Если
ручной профиль не совпадает с реальной системой (или дистрибутив/пакетный
менеджер не определён), `package_ops_allowed=False`: изменяющие пакетные
инструменты возвращают ошибку, не доходя до `PackageManager`. Файловые
инструменты при этом работают.

## Тесты

- `tests/test_llm.py` — загрузка сценариев, подстановка групп, fallback, ошибки JSON.
- `tests/test_agent.py` — шаги, подтверждение и отмена, лимиты, повторы,

  успешная установка пакета (фейковый менеджер), поиск файла, удаление
  с подтверждением, ошибка пакетного менеджера, исправление аргументов.
- `tests/test_gui.py` — запуск цикла в окне, панель задач, диалог подтверждения,
  отчёт в чате, недоступный бэкенд.
